# v0.2.0 统一发布设计

## 目标与授权
用户要求统一正式源码、GitHub 发布、安装版本与 OB/布丁手册。本次允许跨仓同步。
公开基线为 v0.1.2；目前检索到的旧工作树与基线一致，未找到手册 v0.2 的完整候选实现。
因此本次明确补齐报告展示层，不声称恢复了原候选。

## 范围
保留三层十五维风险判断与逐条确认修改流程。内部每维风险 0—2、每层 0—10 不变。
用户层三项健康分分别为 10 减对应风险分，越高越好，不计算总分，不表示来源概率。
报告输出顺序：一句话结论、健康概览表、最多三项优先动作、每层现状/依据/建议、
十五项细分风险、保护清单、需作者补充的信息、完整依据。
未选择的层不展示；停止层不发健康分。无问题不编造动作。表格替代旧手册中未实现的雷达图承诺。
无新的检测模型、无外部检测器调用、无全文改写。结构通过不冒充跨场景实际效果。

## 架构与兼容
新增独立 plain_report.py 展示模块，review_contract.py 保留快照、判断和校验。
JSON 内部风险字段含义不变；版本固定为 0.2.0。旧归档保留旧版本不篡改。
P0 的 risk_score 明确为 null；校验和 schema 同步允许且验证停止分支。
模板单次替换，来源文本中的双花括号保持原样。

## 验收与发布
运行 unittest、便携自测、单层/停止/模板注入/分数方向回归。
两篇授权 OB 文章作为人工判读的端到端回归，只在本地保存正文，不提交 GitHub。
无凭证、私人路径、文章正文进入公开仓库。
验证后备份应用、显式文件提交、推送 main、发布 v0.2.0，再隔离安装验证。
OB 与线上手册只在远程发布成功后标记正式发布，并添加仓库和 Release 链接。
任何环节失败如实记录，不能称全链路完成。
